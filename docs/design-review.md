# paperatomy 工程审计与路线图（对标标准软件）

> 2026-11-10 · 全链路自查：一个「给人用的本地软件」从头到尾需要什么，
> 我们有什么、缺什么、按什么顺序补。每一条都对照当前代码核实过，不是拍脑袋。

## 一、现状盘点（先说达标项）

| 维度 | 现状 | 结论 |
|---|---|---|
| CI | `.github/workflows/tests.yml`，173 项测试 | ✅ |
| 发布纪律 | 语义化版本 + CHANGELOG + 双远程 tag + GitHub Release（v0.1.0→v0.12.0 共 20+ 个） | ✅ |
| 安全边界 | 只绑 127.0.0.1 · 写操作 same_origin 校验 · report_path 路径穿越校验 · 上传 120MB 上限 + `%PDF` 头校验 | ✅ |
| 模型容错 | 限流退避重试、修复循环、论证链失败不拦报告 | ✅ |
| 文档 | README 可跑通、docs/ 设计文档、CHANGELOG | ✅ |

**结论：产品闭环和发布纪律已经是合格开源软件。缺口集中在「坏了怎么办」和「用久了会怎样」。**

## 二、后台可能遇到的问题 → 解法

### P0（信任问题：坏了要能查、能恢复）

**1. 没有日志落盘** ⚠️ 当前最痛
- 现状：日志只进黑窗口，窗口一关，出过什么错永远查不到。用户报障只能靠截图。
- 解法：`logging` 标准模块 + `logs/serve.log`（按天轮转，保留 7 天）。
  请求错误、任务起止、模型调用失败全记。错误徽章旁加「打开日志」。

**2. 任务状态不持久化**
- 现状：任务只在内存里。分析跑到一半关窗口/断电，重启后一切归零，
  用户不知道刚才那篇到哪了，只能重新上传重跑（重新花钱）。
- 解法：任务登记落盘 `out/.tasks.json`（状态/阶段/开始时间）；
  重启后工作台显示「上次有 1 个任务在 03 阶段中断，是否重新分析该论文」。
- 进阶（P1）：分阶段断点——解析结果、抽取结果各阶段落盘，重跑只从断点开始。

**3. 两类 PDF 会产出垃圾报告而不是报错**
- 加密 PDF：`parse` 直接失败或乱码 → 应检测 `doc.needs_pass`，明确提示「PDF 已加密，请解除密码后上传」。
- 扫描版 PDF（无文本层，纯图片）：能"成功"解析但抽不出内容 → 空报告浪费一次模型调用。
  应在解析后检查文本量阈值（如 < 500 字符），提示「扫描版 PDF 暂不支持（需 OCR）」。
- 解法：`parse.py` 入口加两项检测，走统一的友好报错。

### P1（用久了会撞上）

**4. 并发任务的排队**：第二个任务现在直接 409「已有任务在跑」。
批量上传已在前端排队，但两个浏览器标签/两次拖拽仍会撞。
解法：服务端 FIFO 队列（列表 + 状态），任务卡显示「排队中，前面还有 1 篇」。

**5. 磁盘无限增长**：out/ + papers/ + pages/ 缓存只增不减。
解法：诊断面板加「占用统计」（各目录 MB 数）+ 一键清理页面图缓存；报告总量提示。

**6. 端口冲突的友好化**：有处理但不完善——双开工作台时第二个实例应检测到
8770 已被自己人占用，直接打开浏览器指向现有实例，而不是报错。

### P2（锦上添花）
- 版本更新检查：启动时查 GitHub latest release，提示「有新版本」。
- 一键诊断包：错误徽章旁加「导出诊断信息」（版本 + 最近 50 行日志 + 系统信息），
  用户找 AI 修问题时一键给全上下文。

## 三、用户会遇到的问题 → 解法

### P1

**1. 设置入口缺失**：改 API key / 查用量要开命令行。
解法：工作台左栏「设置」面板——填 key（掩码显示）、看模型名、看本机用量估算。

**2. 搜索太浅**：只搜标题和文件名。
解法：全文搜索——同时匹配 findings 内容与题注（SQLite LIKE 已够用，百篇以内无性能问题）。

**3. 排序缺失**：只有按时间。
解法：排序 chips（最近 / 标题 / 页数）。

**4. 误删无法恢复**：删除有确认但删了就是删了。
解法：删除改为移入回收站（`out/.trash/` 保留 7 天），诊断面板提供恢复入口。

**5. 报告转 PDF/打印**：答辩要交 PDF 版报告。
解法：报告页加 print 样式（隐藏按钮侧栏、图表分页友好）+「打印 / 存为 PDF」按钮，走浏览器打印。

### P2
- 追问历史持久化（刷新即丢，可存 localStorage 或报告 JSON）。
- 离线报告的显式提示：静态 HTML 打开时顶部加「离线模式：追问/数据动图需本地服务」徽标（现在部分功能静默失效）。

## 四、明确不做（控制 scope）

- 账号系统 / 多用户 / 云同步 —— 本地工具，定位如此
- OCR —— 工程量大且非核心，明确报「不支持扫描版」即可
- 移动端适配 —— 桌面演示场景优先
- 自动更新安装 —— 只做「有新版本」提示

## 五、推荐实施顺序

| 轮次 | 内容 | 理由 |
|---|---|---|
| 下一轮（P0） | 日志落盘 + 任务持久化/中断恢复 + 加密/扫描版 PDF 检测 + 回收站 | 全是「坏了怎么办」，直接决定软件可信度；工作量小、见效大 |
| 再下一轮（P1） | 服务端排队 + 工作台设置面板 + 全文搜索/排序 + 打印导出 | 用久了必撞；每项都不大 |
| 有余力（P2） | 更新检查 + 诊断包 + 断点续跑 + 磁盘管理 | 锦上添花 |

## 六、一句话定位（答辩可讲）

> paperatomy 的工程标准：**本地优先、失败可见、一切可恢复**——
> 日志可查、任务可续、误删可救、异常输入明确拒绝而不是产出垃圾。
