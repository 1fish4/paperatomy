# 动态讲解核心技术方案

> 目标：把「一篇论文的核心逻辑」变成一段**可操作、可核对、可导出**的动画讲解。
> 本文梳理现状、指出短板、给出分级演进路线。每一步都守住项目铁律：
> **固定渲染引擎，不固定叙事；最终状态写进 DOM，动画只做装饰。**

---

## 一、现状架构（v0.15.0）

```
报告 JSON（已完成抽取）
   ↓  材料组装   findings 摘要 + 背景/已有做法/不足/对比板块 + 论证链 + 关键数字
   ↓  LLM 一次调用                    ── 约 30 秒，一次调用不拆分
分镜脚本 JSON（demo_script，缓存进报告 JSON）
   ↓  _norm_demo 程序校验              ── 镜数上限、字段规范、viz 类型白名单、坏镜降级
scenes[]: 每镜 = { narration(旁白≤90字), viz(画面数据) }
   ↓  前端渲染引擎（report_template.html）
6 种固定画面原语 + 播放器（播放/暂停/上下镜/进度点，6s 自动推进，#demo 深链）
```

**六种原语与表达力边界：**

| 原语 | 演什么 | 现状 |
|------|--------|------|
| `mindmap` | 全文骨架（中心 + 分支卡） | ✅ 开场镜，强制 |
| `tokens` | 元素堆分组/点亮，演构成与分布 | ✅ |
| `flow` | 流程逐步点亮，演方法步骤 | ✅ |
| `compare` | 左右对比卡，演已有方法 vs 本文改进 | ✅ |
| `bars` | 柱状生长，演量化对比 | ✅ |
| `line` | 折线画线，演趋势 | ✅ |

**三条可信链路（区别于「AI 生成动画」玩具的关键）：**

1. **数字不编**：所有数值来自报告 JSON 已抽取并经证据定位的数据，模型只搬运；
2. **画面不飞**：模型输出经 `_norm_demo` 白名单校验，坏镜自动降级为纯旁白，播放器永不空屏；
3. **最终态先写**：SVG 属性里写好终值，入场动画只是装饰——headless/低性能环境也能看全。

---

## 二、为什么还不满意（短板清单）

1. **镜内是单拍**：一个镜 = 一幅静态画面 + 一段旁白。「先这样、再那样」的**镜内演变**演不了
   （比如：任务先堆在高碳时段 → 再看它们被挪到绿电时段——现在要拆成两个镜，叙事断裂）。
2. **原语是"展示"不是"操作"**：能"看见"结构，不能"看见过程"——没有连线、移动、
   吞并、分裂这类**实体动作**，方法的核心机制（谁被映射到谁、什么替换了什么）只能靠旁白说。
3. **旁白与画面不同步**：旁白是整段显示，画面是统一入场动画，观众不知道现在该看哪。
4. **不可导出**：只能在线播，答辩 PPT 里插不了，也分享不出去。
5. **材料瓶颈**：分镜质量上限由材料决定，摘要级材料讲不出机制细节。

## 三、核心技术方案：四级演进

### L1 —— 镜内节拍（把「镜」升级为「拍」）★ 下一步就做这个

**核心改动**：一镜 = N 个节拍（beat），每拍 = `{ say, act }`：

```json
{"title": "把任务挪进绿电时段", "type": "tokens",
 "beats": [
   {"say": "现在，任务全挤在高碳时段硬跑。",
    "act": {"kind": "show", "group": "tasks", "state": "red"}},
   {"say": "作者的办法不换机器，只挪开始时间。",
    "act": {"kind": "highlight", "group": "tasks"}},
   {"say": "挪进绿电窗口，碳排立刻下来。",
    "act": {"kind": "move", "from": "red-zone", "to": "green-zone", "n": 6}}
 ]}
```

- 渲染器按拍推进：每拍切换时旁白更新 + 对应画面动作执行；自动模式下按拍计时。
- **兼容性**：`beats` 是可选字段——只有 `narration + viz` 的旧镜照常工作（单拍镜）。
  模型 prompt 里鼓励给关键镜写 2~3 拍，其余镜保持单拍，控制生成成本。
- `act` 原语只有四个：`show / highlight / move / swap`，渲染器写死，模型只能填参数。

**为什么先做它**：改动最小（播放器加一个"拍指针"），但直接解决"叙事断裂"和
"旁白画面不同步"两个最大痛点。

### L2 —— 关系原语（演"机制"而不只是"结构"）

新增三种带实体动作的原语，专攻方法机制：

- `mapping`：两列实体 + 连线动画——演"任务→机器""查询→文档"这类映射，连线逐条亮，
  谁连谁都看得见（RAG、调度、匹配类论文的核心画面）；
- `transform`：一组块 → 箭头 → 另一组块，**块内可标注符号**（如 `QK^T → 稀疏近似`），
  演结构替换；承接论证链 `change` 节点的 before/after 规格复用；
- `pipeline`：横向管道 + 数据流粒子——数据从左流到右、在每站变色，演端到端系统。

校验规则同步收紧：`mapping` 的连线两端实体必须出现在材料里；`transform` 的符号
串必须来自论文原文（复用证据定位器回查，查不到就降级为 `flow`）。

### L3 —— 分镜质量闭环（材料与自评）

- **材料升级**：给分镜调用单独组装材料——方法章节全文（不压缩机制段落）+
  论证链 + 图表解读。机制讲不清多半是材料里根本没有机制段落。
- **自评修复循环**（复用抽取链的成熟模式）：首轮生成 → 程序校验（拍数、act 参数、
  数字可读性）→ 把问题回喂重试（最多 2 轮）。成本约 ×1.7，只对首次生成生效。
- **可选人工微调**：报告页分镜脚本周边加"编辑"入口，直接改旁白文字（不碰画面数据），
  改完存回 JSON——答辩前自己顺一遍词，比重新生成靠谱。

### L4 —— 导出与分享

- **GIF/视频**：播放器逐拍驱动的是 DOM/SVG，导出用**离线合成**而非录屏——
  按分镜 JSON 用 Python + Chrome headless 逐拍截图帧，ffmpeg 合成 mp4/gif，
  附旁白字幕烧录。产物可进 PPT、可发推，全部本地完成。
- **深链分享**：`#demo&s=3&b=2` 支持定位到第几镜第几拍，讲解者可以从任意位置开始。

### 明确不做

- **不生成真正的程序动画**（物理引擎/粒子仿真）：表达力无边，成本无边，且无法核对。
  六种 + 三种原语覆盖"构成/流程/对比/趋势/映射/替换/管道"七类论文核心叙事，够了。
- **不做语音合成**：旁白文字本身就是讲解；TTS 是锦上添花且引入新的质量风险。
- **不用视频生成模型**：无法保证数字与结构正确，且不可核对——与项目"每句话有出处"
  的立身之本冲突。

## 四、里程碑与验收

| 级别 | 内容 | 验收标准 |
|------|------|----------|
| L1 | 镜内节拍 | CaWoSched 重生成后，问题镜与效果镜各含 2~3 拍；旧脚本兼容不报错 |
| L2 | 关系原语 | mapping/transform 的实体与符号 100% 可回查到材料，查不到自动降级 |
| L3 | 质量闭环 | 首轮校验不合规项收敛（≤1 轮修复）；旁白可人工编辑并持久化 |
| L4 | 导出 | 一键导出 720p mp4（含字幕），文件 < 10MB，可在 PPT 播放 |

**成本预估**：L1/L2 仅前端 + prompt 改动，生成成本不变；L3 首次生成 ×1.7（几分钱级）；
L4 导出零模型调用。单篇全程依然控制在几分钱。

---

## 五、与既有设计的关系

- **论证链是分镜的素材库**：`change` 节点的 before/after 直接映射 `transform` 镜，
  `effect` 的 metric 直接映射 `bars/line` 镜——两条链路共享同一套可信数据。
- **证据定位是分镜的护栏**：画面里的符号、实体、数字都能回查原文，查不到就降级。
- **模板无关**：动态讲解读的是报告 JSON，不挑模板——速读、精读、综述都能讲。
