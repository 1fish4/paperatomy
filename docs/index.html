paperatomy · 论文解剖

把一篇论文拆成一张结构图

不是和它聊天，是让它自己交代清楚：研究问题、背景、方法、数据、结论、局限。

每块都附页码与原文摘录，可以逐条核对。方法流程与分类框架还能逐段播放。

论证链

这不是模板。链条的节点数、类型、顺序由每篇论文自己决定， 固定的是渲染引擎。「改动」环节必须给出改动前后的对照—— 上面这张图里，左边是原始注意力（QK^T 全对全），右边是替换后的结构， 差异被直接画出来，而不是用文字描述。

「改进具体体现在哪里」

这是最容易含糊、也最该说清的一句话。所以 change 节点必须同时给 before 与 after 两份图示规格： 一排 token 用 1.5 的节奏点亮，另一排用 0.4——速度差异被看见，而不只是被描述； 一排模块块高亮被替换的那一块，新旧用暖冷两套颜色分开。

它长什么样

正文每一块底部列出原文页码与摘录；低置信度的判断会单独标出。

为什么不是「和 PDF 聊天」

聊天工具要求你先知道该问什么 —— 而「不知道该问什么」正是读不懂的状态。 这里骨架是预设的，打开即完整，不需要你提问。 另外每句话都有出处：聊天给你一段话，你不知道它从哪来。

三条不许破的规矩

没有依据的改动不许画。「改动」与「效果」两个环节没有页码与原文摘录，直接判不合法—— 一个编出来的动画比没有动画更糟。
效果必须是数字。「显著提升」会被打回，「2.6×」才通过。
抽不出来就不抽。空链是合法结果：纯理论论文没有「改动前后」，强行编一条反而有害。

自己跑

git clone https://github.com/1fish4/paperatomy.git
cd paperatomy
pip install -e ".[dev]"

paperatomy config set --api-key sk-xxx --model deepseek-chat
paperatomy extract paper.pdf -t survey -l zh -o out/paper
paperatomy chain out/paper.json     # 已有报告单独补论证链

产出三个文件：.json（结构化）、.md（贴笔记）、 .html（单文件报告，含可播放的演示）。

关于示例：两份示例报告的内容由大模型从论文原文抽取，引用为英文原句的短摘录， 版权归原作者所有，此处仅用于演示工具效果。论文原文不在本仓库内。
