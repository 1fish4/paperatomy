# 论证链：把一篇论文的推理线演出来

> 本文回答两个问题：
> **怎么让「每一篇论文自己的逻辑」被看见？** 以及 **为什么不用固定模板？**

---

## 一、先承认一期做错了什么

0.2 版做了三个固定原语：`pipeline`（方法流程）、`example`（例子走查）、`taxonomy`（分类框架）。

问题不在画得丑，在**结构也被固定了**：

```
每篇论文 → 套进「三段流程」→ 出来的图长得一模一样，只有文字不同
```

那不是「大模型在推理」，那是**填空题**。用户的原话是「演示有点 low」，
根因就在这里——你看到的是同一个模板的第 N 次复用。

## 二、正确的分工

```
固定的：渲染引擎   ——  怎么排版、怎么动、怎么标注差异
不固定的：叙事结构 ——  这篇论文凭什么、改了什么、效果在哪、代价是什么
```

前者必须是代码（要稳定、可校验、可复用）；
后者必须由模型按论文自己生成（否则就是模板）。

所以只保留一个原语：**`chain`**——一条属于这篇论文的论证链。

## 三、链条长什么样

模型的输出是一条**线性**的节点序列，每个节点有类型：

| 类型 | 中文 | 要求 | 作用 |
|------|------|------|------|
| `problem` | 问题 | 能量化就量化 | 论文要打的靶子 |
| `insight` | 洞察 | — | 作者的关键判断：为什么这条路可能通 |
| `change` | 改动 | **必须 before / after 图示** | 具体改了什么 |
| `mechanism` | 机制 | — | 通过什么起作用 |
| `effect` | 效果 | **必须带数字** | 量出来的结果 |
| `cost` | 代价 | — | 失效条件、适用边界 |
| `taxonomy` | 框架 | 树结构 | 分类体系（综述常用） |
| `question` | 待解 | — | 尚未解决的问题 |

**节点数、类型组合、顺序全部由论文决定。** 一篇方法论文通常是
`问题 → 洞察 → 改动 → 机制 → 效果 → 代价`；一篇综述可能是
`问题 → 洞察 → 框架 → 效果 → 待解`。

### 为什么强制线性

分叉的图更"信息丰富"，但一条论证本来就是一条线：

> 作者为什么这么做 → 做了什么 → 凭什么有效 → 结果如何

拆成两条并行支线，读者就得自己做拓扑排序。**一条链最多 8 个节点**，
超过 8 个说明这不是一条论证，是一份提纲。

## 四、`change` 是整条链的眼

用户的原话：

> 做一个机器学习模型改进的，那我们就演示他的**改进具体体现在哪里**

「改进体现在哪里」只能靠**前后对照**看出来。所以 `change` 节点必须给两份图示规格：

```json
{
  "type": "change",
  "label": "串行生成改为先猜后验",
  "before": {"kind": "tokens", "n": 9, "label": "逐 token 串行", "cadence": 1.5},
  "after":  {"kind": "tokens", "n": 9, "label": "草稿 + 并行验证", "cadence": 0.4}
}
```

前端并排画出来，中间一个箭头，两边的 color 也分开（前=暖色，后=冷色）。

**`cadence` 是这里最关键的设计**：它不描述"更快"，它让"更快"发生——
同一排 token，`1.5` 的间隔要点 1.7 秒才亮完，`0.4` 只用 0.47 秒。
**速度差异被看见，而不只是被描述。**

## 五、图示规格只有四种

AI 不画图，只填参数。四种够用，多了模型会乱用：

| kind | 长什么样 | 什么时候用 |
|------|---------|-----------|
| `tokens` | 一排方块逐个点亮，`cadence` 控制节奏 | 生成、迭代、逐步处理——**速度差异** |
| `blocks` | 一排模块方块，`highlight` 高亮某块 | 结构改动：某块被替换 / 删除 / 新增 |
| `bars` | 横向指标条 | 结果对比（基线 vs 本文） |
| `text` | 一句话 | 实在没法图示时的退路 |

```json
{"kind": "tokens", "n": 8, "cadence": 1.4, "label": "逐 token 串行"}
{"kind": "blocks", "items": ["Attention", "FFN", "Norm"], "highlight": 0}
{"kind": "bars", "items": [{"label": "基线", "value": 1}, {"label": "本文", "value": 2.6}], "unit": "×"}
{"kind": "text", "text": "作者未给出可图示的结构变化"}
```

## 六、三条硬约束（写进校验，不靠自觉）

**1. 没有原文依据的改动不许画。**
`change` 与 `effect` 节点没有 `evidence`（页码 + 原文摘录）直接判不合法。
一个编出来的动画比没有动画更糟。

**2. 效果必须是数字。**
`metric.value` 要能被程序读出数（`"2.6"` 而不是 `"显著提升"`）。
原文给区间（2–3×）就取下界或中位数，并在 `detail` 里写明区间。

**3. 抽不出来就不抽。**
空链是**合法结果**。纯理论推导、纯数据集论文本来就抽不出论证线。
`parse_chain_response` 特意区分两种情况：

- 返回 `None` = 输出解析不了 → 走修复循环
- 返回空 `nodes` = **模型明确说这篇没有可演的链** → 接受，不逼它重编

这个区分很重要。不区分的话，模型会被校验逼着编一条假链出来。

## 七、还有一类提示：不是错误，是论文没写清

有些问题不该拒绝渲染，但必须让人知道：

| 提示 | 含义 |
|------|------|
| 链条里没有「机制」环节 | 看不出改动为什么有效 |
| 链条里没有「效果」环节 | 结论缺少可核对的数字 |
| 链条里没有「代价」环节 | 论文可能没讨论适用边界 |
| 某个 `change` 只能用文字描述 | 论文没给可图示的结构差异 |

**工具应该跟着论文一起不确定，而不是替它补一个听起来合理的理由。**

## 八、边界（诚实版）

**做不到的：**

- **不是真动画。** 没有插值、没有物理效果、没有转场特效。
  每一帧都是声明式渲染 + CSS 过渡，不是渲染出来的视频。
- **演不出公式推导。** 定理证明没有"改动前后"可言，`change` 无从下手。
- **演不出跨论文对比。** 一条链只属于一篇论文。
- **`tokens` 不是真的在执行算法。** 它只是用节奏象征速度，不是模拟真实解码过程。

**为什么不做真动画（比如生成 Manim 视频）：**

那需要把论文方法翻译成可执行程序，是研究级难题，且每篇论文都得重来。
而本项目要保证**任何用户、任何论文都能跑**，所以只能走"声明式参数 + 手写渲染"这条路。

## 九、加一种节点类型 / 一种图示

**加节点类型**（`paperatomy/chain.py`）：

1. 往 `NODE_TYPES` 加一项
2. 需要特殊校验就在 `validate_chain` 里加分支
3. 前端 `detailHTML()` 加渲染分支（不写也能跑，会退化成纯文字）

**加图示**（三处）：

1. `DIAGRAM_KINDS` 加名字
2. `_check_diagram()` 加校验（范围、必填字段）
3. `diagramHTML()` 加渲染分支，`styles` 加样式

新加的东西必须能回答一个问题：**它演的是哪一种"看懂"？**
答不上来就别加——多一种画法只会稀释注意力。
